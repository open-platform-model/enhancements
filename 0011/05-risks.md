# Risks, Drawbacks, Alternatives — Module and Catalog Publishing

This document records the honest costs of the proposed design. Risks describe what could go wrong; Drawbacks describe what definitely costs something; Alternatives describe the high-level paths not taken (per-decision detail lives in `03-decisions.md`).

## Risks and Mitigations

- **~~The namespace move rewrites every published coordinate~~ — retired 2026-08-04 by D13 and D17.** This was the largest risk in the entry while D5 moved every module to `opmodel.dev/m/<owner>/<name>`. D13 keeps first-party modules at `opmodel.dev/modules/<name>`, so no coordinate is rewritten, no `registryPath` moves, and no instance identity derived from one changes. What replaces it is a bounded cleanup (D17) with the **opposite** sequencing: the legacy `v1alpha1` repositories must *wait* for the v0 → v1 fleet migration rather than being done early, because the deployed fleet still pins them. The retired claim that "delay is strictly more expensive here than anywhere else" is false — nothing compounds, because nothing moves.

- **A vanity domain is an ownership claim that nothing verifies.** D13 makes path ownership domain ownership, and no mechanism checks domain control today — nothing prevents a push to `microsoft.com/evil` on a registry that accepts it. Blast radius: impersonation in the namespace, which is worse than the name collisions owner-scoping was defending against. **Mitigation:** D13 states proof-of-control as a requirement on the registry rollout and leaves the mechanism open, matching D10's and D11's boundary. The exposure is bounded while the central registry does not yet exist; it becomes live on the day it does, so this is a gate on standing the registry up rather than on this design.

- **A mutable tag makes every downstream guarantee conditional.** If a tag can be overwritten under a consumer who already resolved it, a pinned version stops naming fixed bytes and every digest comparison silently checks a moving target. Blast radius: reproducibility across the whole ecosystem, plus a time-of-check-to-time-of-use vector. **Mitigation:** D10, resolved two-sided — a registry-side immutability requirement binding any conforming registry, plus a client-side refusal to overwrite an existing tag. Note the client-side half alone is not sufficient, since `cue mod publish` bypasses it. **Residual:** GHCR, which the fleet resolves against today, cannot enforce it, and D10 accepts that deliberately — tag immutability is a property OPM neither has nor claims until a conforming registry is in place. D15's authored-version trigger leans on it, so the two arrive together.

- **An author who forgets to bump gets silence.** Under D15 the authored version is the trigger, so a module whose code changed but whose `Version` did not simply does not publish — nothing refuses, nothing warns by default. Blast radius: a release that everyone believes shipped and did not, discovered late. **Mitigation:** the git-sourced advisory D15 specifies — has anything under the module changed since the commit tagged with its current version. It is deliberately a warning rather than a gate, because a gate here would block the deliberate case of bumping a version with no other change.

- **A refusal that fires too easily gets routed around.** Every gate here is a refusal, and `cue mod publish` remains available as an escape hatch that skips all of them. A gate that blocks a legitimate publish teaches publishers to bypass OPM's tooling entirely, which removes every other gate at the same time. Blast radius: the design's producer-side half becomes decorative. **Mitigation:** each refusal names the offending value, its file, and the action that clears it; the identity-completeness gate is on concreteness rather than on a broader notion of well-formedness; and the catalog override gate — the only unconditional one — is scoped to the presence of a single file that has no reason to exist in a release tree.

- **A refusal in CI reads as a broken pipeline rather than a caught defect.** The local-override gate and the identity gate will first fire inside someone's release workflow, where the default interpretation of a non-zero exit is "the tooling is broken." Blast radius: pressure to add a bypass flag for the wrong reason. **Mitigation:** the message must distinguish itself from a tool failure — state what was found, what would have been published, and what a consumer would have resolved instead.

- **D21's schema shipped ahead of the check that runs it, and it is currently the only statement of the version/path major relation anywhere.** Enhancement 0010 D43 and D45 each deleted a `core`-side version-major assertion, each citing publish-side validation against `#IdentityPackage` as the replacement. `core-identity-package` landed that schema on 2026-08-08 — and nothing unifies against it, because `cli-publish-pipeline` is where D21's unification lives and that slice has not started. The consumer-side catch D43 and D45 named as the residual is also not built: it is library-side, carried by 0010's `library-acquire-and-subscription` slice (formerly `library-subscription-collapse`), which is `planned`. Measured 2026-08-08 — `_majorAgrees` has never existed in `core` at any commit, so this is an ordering gap rather than a deleted safeguard. **Blast radius:** a catalog or module published with a version whose major disagrees with its path is accepted by every check that exists today, and under 0010 D4 a wrong key is permanent — modules match against it forever. `cue mod publish` (D11) reaches the registry without passing any of this regardless. **Mitigation:** the window closes from either end and both ends have named owners, so this is scheduling rather than design — but the two slices are independent, and until the first of them lands the relation is asserted by a schema no tool runs. Do not read `#IdentityPackage`'s presence in `core` as the check being live; the entry's own graduation gates require the CLI half, and they are the honest measure.

## Drawbacks

- **Releasing gains a step.** `version set` → review → commit → `publish` is four operations where `task publish VERSION=…` was one. Accepted: the added operation is the commit, and it is the thing that makes an artifact traceable to a source state. The ephemeral-CI case keeps a one-command path — D12 resolves `--version` to write the working tree, so automation with no human to review a diff runs `publish --version X.Y.Z` alone.

- **A local development tree cannot be published without an explicit act.** An author who has been working against local replacements must remove or bypass them before a release. Accepted: that is the point, and the alternative is an artifact that resolves against dependencies nobody validated.

- **Catalog authors lose an escape hatch that module authors keep.** The asymmetry is deliberate (D6) but it is still an asymmetry someone will hit and have to be told about, and "why can I force this for a module but not a catalog" is not self-evident from the error alone. Accepted: the message must carry the reason, not just the rule.

- **`opm` becomes the required path to a correct publish.** `cue mod publish` still works and still bypasses every gate, so the design's producer-side guarantees hold only for people who use OPM's tooling. Accepted, and bounded by design: the guarantees consumers actually rely on live on the read paths in enhancement 0010, which no publisher can bypass. This entry makes conformance the default; it does not make it inevitable.

- **`opmodel.dev/modules/<name>` is now permanent, and `modules` is a grandfathered spelling.** D13 declined the rename to `m` on migration cost, so first-party modules keep a segment that the community space spells differently. Accepted with the reason recorded (D13): the asymmetry buys a fleet that does not move, and D10 makes any later rename strictly more expensive than it is today. The `community.opmodel.dev` namespace is the genuinely one-way part, since nothing is published there yet and everything published there later is permanent.

## Alternatives

- **Keep publishing in repo-local Taskfiles and fix them individually.** **Why not:** it is the current state, and it produced three different answers to "what version is this artifact" plus a catalog flow that publishes bytes that never existed in git. Each Taskfile is correct on its own terms and none of them can enforce anything on the others.

- **Publish by wrapping `cue mod publish` with pre-flight checks only, adding no commands.** **Why not:** it leaves version authoring unowned, which is where the drift originates. A wrapper can refuse a bad publish but cannot make a good one easy, so the pressure to bypass it stays.

- **An index-only central registry, with authors *hosting* under their own domains.** **Why not:** CUE resolves a module path to a host through the `CUE_REGISTRY` prefix mapping with no per-domain autodiscovery, so a self-hosted artifact is unresolvable for every consumer who has not first edited their own configuration. Zero-setup consumption and host-anywhere are not simultaneously available. Note this rules out foreign *hosting*, not foreign *paths* — D13 permits any path on OPM's registry, because a bare host in `CUE_REGISTRY` is a catch-all and the path's domain never has to match the host.

- **Owner-scoping every artifact under `opmodel.dev`.** **Why not:** it makes OPM the registrar for names it does not own, which is the position D5's own rationale wanted to avoid and which has no good spelling for first-party (`opmodel.dev/c/opm/opm`). D13 replaces it with domain ownership, and gives publishers without a domain `community.opmodel.dev/m/<owner>/<name>` instead.

- **Let release automation write identity files directly** — release-please can rewrite a version in an arbitrary file through an `x-release-please-version` comment annotation, so a `.cue` file would work. **Why not:** it creates a second writer of the same field, operating outside the command that owns it, which is the exact shape of drift this design removes. Automation should call the command instead.
