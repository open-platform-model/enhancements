# Risks, Drawbacks, Alternatives — Kernel render path parity with pure CUE

## Risks and Mitigations

- **A fixture starts shipping a broken value instead of no value.** `TestFlow_WebApp_OnOpmPlatform` builds its instance by `LookupPath` plus `FillPath`, which severs the reference that wires `#instance`. Today `#names.dns.fqdn` is unreachable, so the defect is invisible; once definitions are exposed it becomes a concrete wrong answer (`required field missing: namespace`) that a naive reading blames on this enhancement. Anything else in the workspace constructing instances the same way inherits it. **Mitigation:** the fixture repair is inside the slice that exposes definitions, not after it (D4), and `cli` and `opm-operator` are swept for the same construction shape before that slice lands.

- **The ADR-003 closedness corruption returns through a path not covered by the probe.** The hazard was reproduced once, on one shape (an output-local hidden field consumed in-expression), on the federated surface. A different composition could still trip the unfixed upstream CUE Go-API bug that ADR-003 documents as open. **Mitigation:** both existing regression guards stay in the suite unchanged and gate every slice; the `cueregression` canary pair continues to pin the evaluator behaviour in both directions; the parity harness adds a second, independent detector, since a corrupt value diverges from the CUE oracle by construction.

- **The parity oracle disagrees for reasons that are not defects.** `#context` is projected differently on the two sides (Go-built versus CUE-derived), and a naive structural comparison could fail on field ordering, absent-versus-null, or defaults. A harness that cries wolf stops being read, which is the failure mode of every coverage check. **Mitigation:** the equality is specified before the harness is written (a `draft → accepted` gate, met by `#ParityCase` and the fixture enumeration in `02-design.md`), and D12's projection removes the largest source of legitimate disagreement once its slice lands; until then cases compare `output-fields-only`.

- **`#57`'s nondeterminism becomes load-bearing for rendering.** Definitions on the schema-side component value have been observed going silently absent under catalog-version skew. Match already depends on that value, so the exposure is not new, but rendering would inherit it. **Mitigation:** the exposure is bounded by the fact that 0010 closed the skew window at its source; the parity harness would surface a recurrence as a divergence rather than as an empty match. Not fully mitigated: this is a known residual, and it argues for keeping `#57` open until the harness has run against a skewed tree.

- **The single-build reading is wrong in a way eight experiments did not catch.** OQ1 through OQ3 are ratified into D9, so this risk is now residual rather than open: the remaining exposure is an unmeasured consumer depending on federation behaviour, or a load-path behaviour that differs off the `cue v0.17.1` evaluator everything was measured on. **Mitigation:** the parity work (D1 through D4) is independent of the collapse and delivers value on its own; `plan.yaml` keeps Phase A free of Phase B dependencies, so a Phase B stall strands nothing.

- **Every performance and safety number is one evaluator, one host, one day.** The cost model, the crossover, the 4x concurrency, the race counts and the retention figures were all measured on `cue v0.17.1` on one machine on 2026-08-19 — in a repo that pins a canary pair precisely because this evaluator line has a known unfixed regression. A CUE minor could move any of them. **Mitigation:** the correctness argument (D1, D9's structural parity) does not depend on the numbers; the numbers gate only the *ordering* of Phase B against alternatives already rejected on other grounds. Re-run experiments 04 and 07's harnesses after any SDK bump that lands mid-implementation.

- **D5 is a breaking `core` schema change with a small but real blast radius.** `#Subscription` closes around `enable` + `version!`, so the reshape cannot be additive; every platform file and the operator's typed CR mapping move together. **Mitigation:** platform files are few and first-party today (the v2 line is pre-GA alpha); the slice carries the `SPEC.md` co-update under the `core-schema-edit` protocol and lands before any downstream consumer is promised stability.

- **D10's error quality regresses unacceptably in practice.** The verbatim CUE cause `oerrors.UnifyError` carries today is not recoverable from inside the build without a second diagnostic evaluation, and experiment 05 measured shape, not operator ergonomics. **Mitigation:** the fallback is recorded inside D10 itself — keep matching in Go reading the single build's value — and the slice's gate (exact pair-set reproduction against the vendored kernel record) is independent of which side wins.

- **D6 couples the operator to package generation before 0015's registration flow exists.** The generated platform package is where 0015's runtime-discovered transformer sets must fold in (OQ9/OQ10, deferred there), and building the generator without that hook risks a second reshape. **Mitigation:** the generation step ships with a named extension point for the effective transformer set, and 0015's re-baseline is triggered by this entry reaching `accepted`, so the two designs meet before either implements the joint surface.

- **The catalog sweep couples a catalog release to a kernel capability.** A `catalogs/opm` release whose transformers read `#component.#names` renders only on a kernel carrying the Phase A fill; on an older kernel every such transformer fails with the empty-disjunction error, and no CUE dependency expresses "requires a kernel at least this new". **Mitigation:** release ordering, stated in `06-operational.md` step 6 and D15's gating; the v2 line is pre-GA alpha, so the exposure window is first-party.

- **D16's legibility assertion cannot be written unconditionally.** A component authoring an explicit short `resourceName` is legal even when the qualified concatenation would overflow 63 runes, and CUE cannot see from inside the value whether the default was selected, so a naive hidden assertion refuses legal values. Recorded as a SKETCH at the field in `schemas/target.cue`. **Mitigation:** the `core-resourcename-default` slice scopes the assertion (or restructures the cascade) and `schemas/examples.cue` carries the must-fail case with the observed error text; the fallback is accepting the bare `incomplete value` refusal, which `#ComponentNames.resourceName!: #NameType` guarantees one hop later.

- **The operator races today, before any slice lands.** The live hazard is not concurrent reconciles (every controller runs the default single worker) but one shared `*kernel.Kernel` used by three controllers' goroutines, against `library`'s documented one-Kernel-per-goroutine rule, with no lock anywhere in the operator. **Mitigation:** the `opm-operator-render-serialization` stopgap serialises shared-Kernel access across controllers, not merely the render path; D8's shares-nothing model then removes the shared value entirely.

- **Removing the strip invalidates a documented security claim.** `library`'s security-audit skill names `FinalizeValue` as the central constraint-bypass guard (user-supplied data cannot redefine schema constraints because definitions are stripped). The claim's mechanism goes away in Phase A. **Mitigation:** the pure-CUE control shows unification itself enforces closedness (`_probe.spec.bogus: field not allowed` on the value the transformer receives), which is the stronger guarantee; the `library-finalize-removal` slice rewrites the skill's guidance in the same change, so the documented invariant never dangles.

## Drawbacks

- **Two MAJOR breaks, one per phase.** `FinalizeValue` leaving the public kernel surface is a MAJOR library bump (Phase A), and `version!` leaving `#Subscription` is a MAJOR `core` bump (Phase B, D5) — both landing while `cli` and `opm-operator` actively consume the artifacts. Phasing keeps them separable, at the cost of two migration moments instead of one.

- **Small modules pay the fixed term forever.** A per-render single build costs ~85 ms of catalog resolution and evaluation regardless of module size, so a two-component render is 1.7x-2.1x slower in sequential isolation. The trade is deliberate and measured (throughput and memory win at fleet scale), but a CLI user rendering one small module pays it every time; the module cache keeps the cold 1.76 s cost per-process rather than per-render.

- **Transformers can now reach further than the execution unit implies.** D2 fixes execution at one component and D3 hands the transformer the whole instance, which contains every sibling. Per-pair independence becomes a convention: D11 decided exactly that (reachable, discouraged by authoring contract), accepting the loss of the structural guarantee with open eyes.

- **A new authoring rule that CUE does not announce.** A transformer must re-declare a slot in its own `#transform` body to reference it, because CUE resolves references lexically. This is already true for `#component` and is currently invisible because everyone copies an existing transformer. The moment `#moduleInstance` becomes usable, the rule needs documenting, and its failure mode is a build error naming a missing reference rather than anything about the contract.

- **The harness costs maintenance.** Every render-path fixture now has a CUE twin that has to stay in step. That is the price of the oracle, and it is a real ongoing cost rather than a one-time write.

## Alternatives

- **Codify the current behaviour: declare that transformers see data, not definitions.** Document the strip as the contract, and have `core` expose anything a transformer needs as regular fields. **Why not:** it inverts the dependency, since the schema would then be shaped around a Go-side artifact, and it makes the workaround in open-platform-model/core#49 the first of an unbounded series, one per computed projection.

- **Keep the strip and widen `#TransformerContext` instead.** Plumb each needed projection into the context struct as the need arises. **Why not:** every addition is kernel code, so the surface grows in the opposite direction to D1, and the kernel becomes the arbiter of which computed values a transformer may see.

- **Go straight to the single-build render pipeline.** Skip the incremental fills and collapse the whole path in one change. **Why not:** the questions that once blocked it (MVS override, instance importability, reuse cost) were later resolved by experiments 01 through 08 and ratified into D9, but the ordering argument survives the evidence: the parity fixes are valuable independently, the harness must exist before the collapse to prove it faithful, and `library`'s execution gate names a one-go pipeline rewrite as its example of an oversized request.

- **Fix it in `core` only, via open-platform-model/core#49 and open-platform-model/catalog_opm#44.** **Why not:** those are correct and should still land for their own reasons, because the computed name genuinely does not match the rendered name. But they address one value, and they justify their shape by working around this defect rather than by the semantics they want.
