# Notes for the owner at accept

These two points are clashes that the old text of 0014 holds in its own requirement lines. The conversion is faithful, so it does not rewrite them. The old entry did not hold them as open questions, so they are not in the proposal. The owner decides the wording of the requirements at accept.

- **A bare version in the live instance.** "The exported module version keeps its v prefix" (old 0014:D1:R5) says the exported version carries its `v` prefix. "Completed fields are named in the output" (old 0014:D1:R6) says a render-bearing field, the module coordinate among them, is copied unchanged and never altered. When the live instance carries a bare version, such as `2.1.0`, the two lines disagree: adding the prefix alters the field, and copying it leaves the prefix out. The comment in `evidence/contracts/contracts.cue` (lines 170 to 172) records this case from enhancement 0006: a bare version made a CLI-written instance unresolvable by the operator. The scenarios do not say which form the live object holds.
- **The values warning against the encrypted secret paths.** "Every export that writes values warns" (old 0014:D3:R2) says OPM cannot identify which values are secret. The three requirements that moved in from 0013 ("Secret-bearing export output can be SOPS-encrypted", "Exported secret values are encrypted", "An exported instance renders as the original") encrypt the values at paths marked secret. For those paths the warning is untrue. The same point sits beside the sentence flagged in the 07:05 review of the 0013 move.
